# Nayel Overlay: how the code is laid out

## The game's data: one source, read through shared modules

- Every list of game content (zones, instances, bosses, items, recipes, gatherables, quests, pets...) lives in
  one data table in `app/src/shared`, generated by a script in `app/scripts/fetch-*.mjs` (header "do not
  edit") or kept by hand when no source has it (`dungeons.ts`, `instanceLevels.ts`), with its source and date
  in its header.
- Each table is read through its shared module, which builds what the app uses from it: `instances.ts` (the
  instances' catalogue: kinds, modes, worlds, bosses, item levels, chests, the Nightmares), `worlds.ts` (a
  zone's name and type), `gather.ts` (recipes, gatherables), `sessions.ts`, `equipment.ts`, `servers.ts`...
- Pages, components and the main process call those modules, never a table, and never write their own list
  of game content: a new list goes in a table (or a module built on one), so updating the data updates every
  page that shows it (tables, grids, filters). `app/tests/dataAccess.test.ts` checks the imports.
- Tables and grids are built from the catalogue (every instance, every boss, in the game's order), the
  player's data filling the cells; not from whatever the player happens to have.

## The same thing shown the same way: shared components

- A thing shown in several places has one component or function, with parameters for what differs, never a
  copy per page: a character (`CharName.vue`: their class icon, the name or not), a record's value linked to
  its fight (`FightLink.vue`: a DPS or a time; the fight opens in the page that shows fights, else in its own
  window: `lib/fights.ts` provideFightOpener / useOpenFight), numbers and clocks (`shared/format.ts`
  compact, duration), dates, times, countdowns and counts (`renderer/src/lib/format.ts`: timeOfDay,
  shortDate, longDate, weekdayTime, countdown, lasting, amount...; `app/tests/sharedFormats.test.ts` checks).
- What a page shows of the game's content follows the catalogue's settings (`instances.ts`: the tabs'
  order, the kinds ranked by time alone, the Nightmares' levels), not values written in the page.
- The shared pieces: `CharName.vue` (a character or player: class icon, name, server tag), `CharacterChips.vue`
  (picking characters, one or several), `ui/Chip.vue` (a filter's pill), `ui/EmptyState.vue` (a page with
  nothing yet), `FightLink.vue`, `lib/confirm.ts` useArmed (an action that asks once), `lib/grades.ts` (an
  item's grade: name, colour), `lib/overlay.ts` useOverlay (an overlay window), and the formats.
- No unused import or variable (`noUnusedLocals`): what a change leaves behind goes with it.
- Before writing a piece of UI or a format, look for the existing one (components/, lib/, shared/format.ts)
  and extend it with a parameter rather than writing another.

## Main and the engine

- A store's JSON file is kept through `main/dataFile.ts` (`main/jsonFile.ts`): read once, saved whole (at
  once or after a delay), written beside then renamed, every pending save written as the app quits.
  `app/tests/dataFiles.test.ts` checks no module of main does it its own way.
- The engine's events are described once, `main/engineEvents.ts`; handlers read their fields as typed
  (`tracker.onEvent('loot', (ev) => ev.items)`), never `ev['x'] as T`. A new event or field goes there first.
- A table the engine and the app both need is one file in `app/src/shared` (the buffs, the field bosses'
  monster codes, the pets, the spawns), the engine reading it with `include_str!`; questlog's dungeon data
  comes from one script, `app/scripts/fetch-loot.mjs` (drops, cube bosses, guaranteed chests).
- The engine's packet readers share `tracker/protocol.rs`'s helpers (`u16_at`, `u32_at`, `varint`...); each
  domain's readers are in `tracker/protocol/<domain>.rs`, re-exported (`p::...` everywhere).
- `Tracker`'s methods go in the file of their domain (`tracker/pets.rs`, `players.rs`, `login.rs`, `monsters.rs`,
  `rewards.rs`...: `impl Tracker` there); `tracker/mod.rs` keeps the state and `frame`'s dispatch.
- The main process's windows: `main/windows/frame.ts` makes and places any window, `main/windows/overlays.ts`
  holds every overlay (`measuredOverlay`, `OVERLAYS`), `main/windows.ts` the bubble, the dashboard, the details
  and the game in front, re-exporting the rest: import from `./windows.ts`.
  The files copied from A2Tools DPS Meter stay as copied, to follow upstream.
